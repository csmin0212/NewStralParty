# NewParty

친구들끼리 브라우저로 즐기는 4인 온라인 보드 파티 게임.
**아스트랄 파티(Astral Party)** 의 게임 구조를 참고하되, 규칙과 리소스는 직접 만든다.

- 목적: 판매 X, 친구들끼리 노는 개인 프로젝트
- 설치 없이 **링크 하나로 접속**
- 별도 게임 서버 없이 **방장 브라우저가 호스트** (데바데 초기 방식과 같은 P2P 호스트 구조)

> 원작의 코드 디컴파일, 이미지·사운드 추출은 하지 않는다. 게임 메커니즘만 참고하고, 에셋은 직접 만들거나 무료 에셋을 쓴다.

## 1. 참고 게임 분석 (Astral Party)

| 시스템 | 원작 | 메모 |
|---|---|---|
| 보드 | 15종 칸 효과 + 랜덤 이벤트 | 칸 = 그래프의 노드, 갈림길 가능 |
| 주사위 | 이동·전투 모두 주사위 | 막판 역전 가능한 운 요소 |
| 전투 | 1:1, 카드로 공격 보정, 주사위로 회피 판정 | |
| 카드 | 이동·전투·방해 카드 | |
| 캐릭터 | 10명 이상, 고유 스킬 | |
| 몬스터 | 시간이 지나면 등장, 공격·코인 강탈 | |
| 보스 | 코인이 가장 많은 플레이어를 추적 | **1등 견제 장치** |
| 승리 | 코인으로 레벨업, **먼저 레벨 3** 달성 | |

재미의 핵심: **1등 견제 장치**와 **주사위 역전**. 이 두 가지는 반드시 살린다.

## 2. 우리 규칙 (초안, 수치는 플레이하며 조정)

### 턴 흐름
```
턴 시작 → (카드 사용) → 주사위(d6) 굴려 이동 → 도착 칸 효과
        → 같은 칸에 플레이어/몬스터가 있으면 전투 선택 가능 → 턴 종료
```

### 캐릭터 스탯
`HP`, `ATK`, `DEF`, `EVA` + 고유 스킬 1개

### 전투
- 공격자: `d6 + ATK`
- 방어자는 둘 중 하나를 선택
  - **방어**: 피해 = `max(1, 공격값 - (d6 + DEF))`
  - **회피**: `d6 + EVA > 공격값` 이면 피해 0, 아니면 공격값 그대로 받음
- HP 0 → KO: 코인 절반을 잃고 다음 턴 본부에서 부활

### 경제 · 승리
- 본부 칸에 도착하거나 **지나가면** 코인을 내고 레벨업: Lv1→2 `20코인`, Lv2→3 `40코인`
- 자기 턴 시작마다 코인 +2
- **먼저 레벨 3** 달성한 사람이 승리 (이동 도중이라도 그 자리에서 끝)

> 수치는 전부 [src/engine/rules.ts](src/engine/rules.ts)에 모여 있다.

### 칸 종류 (1차)
| 칸 | 효과 |
|---|---|
| 빈 칸 | 없음 |
| 코인+ | 코인 획득 |
| 코인- | 코인 잃음 |
| 카드 | 카드 1장 뽑기 |
| 몬스터 | 몬스터와 전투 |
| 회복 | HP 회복 |
| 워프 | 다른 칸으로 이동 |
| 본부 | 레벨업 · 부활 지점 |

### 1단계에서 임시로 정한 것
- 몬스터 칸: 내가 한 번 공격 → 못 잡으면 몬스터가 한 번 반격. 방어 선택(방어/회피)은 3단계 전까지 자동으로 '방어'
- 카드 3종 (턴마다 1장, 주사위 굴리기 전에만, 손패 최대 3장): 질주(+2칸), 더블 주사위, 붕대(HP +4)
- 모든 캐릭터 스탯 동일: HP 10, ATK 1, DEF 1, EVA 1

### 이후 추가
몬스터 스폰(라운드 기반), 보스(코인 1등 추적), 캐릭터 고유 스킬, 랜덤 이벤트

## 3. 네트워크 구조

```
[정적 웹사이트]  ← GitHub Pages 등 무료 호스팅, 다들 같은 링크로 접속
      │
[방장 브라우저]   = 게임 로직 + 상태 관리 (판정·주사위는 전부 여기서)
   ↑↓  WebRTC 데이터 채널 (JSON 메시지)
[친구 브라우저들] = 화면 표시 + 입력만

처음 연결할 때만 시그널링(PeerJS 무료 서버) + STUN 사용
연결 후에는 방장 ↔ 친구가 직접 통신
```

### 메시지 예시
```jsonc
// 친구 → 방장 : 행동만 보낸다
{ "type": "ROLL" }
{ "type": "PLAY_CARD", "cardId": 3 }
{ "type": "CHOOSE_DEFENSE", "mode": "evade" }

// 방장 → 모두 : 전체 상태를 뿌린다
{ "type": "STATE", "state": { /* 게임 상태 전체 */ } }
```

### 원칙
- 방장은 **신뢰 기반**. 친구끼리라 안티치트는 넣지 않는다.
- 주사위·랜덤은 방장에서만 굴린다 (시드 기반 RNG).
- 모든 클라이언트가 전체 상태를 받으므로, **방장이 나가면 남은 사람이 마지막 상태로 방을 다시 열어 이어하기** 가능하게 설계한다.

### 알려진 한계
- 방장이 나가면 게임이 멈춘다 → 위의 이어하기로 보완
- 학교·회사 와이파이, 일부 모바일 데이터에서는 P2P 직접 연결이 실패할 수 있다 → 필요하면 무료 티어 TURN 서버 추가

## 4. 기술 스택

- **TypeScript + Vite**
- **PeerJS** (WebRTC 래퍼)
- 렌더링: 처음엔 DOM/Canvas로 단순하게, 필요하면 게임 엔진 라이브러리 도입
- 배포: GitHub Pages (정적 파일만)

### 폴더 구조
```
src/
  engine/   순수 규칙 로직. applyAction(state, action) → newState
            RNG 상태(rngState)도 state 안에 있어서 state만 있으면 이어하기 가능
            UI·네트워크 코드에 의존하지 않는다 (테스트 쉽게)
  net/      (2단계) PeerJS 호스트 / 클라이언트, 메시지 송수신
  ui/       화면, 입력 (지금은 핫시트)
  data/     보드 맵, 카드 데이터
```

### 실행
```bash
npm install
npm run dev     # http://localhost:5173
npm test        # 규칙 엔진 테스트
npm run build   # dist/ 에 정적 파일 생성
```
